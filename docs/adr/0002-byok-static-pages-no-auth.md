# BYOK + 纯静态 Pages：无服务端、无鉴权

原方案曾考虑"服务端持有 Gemini key + 网站访问密码"（让访客开门即用），但它与纯静态架构互斥：静态站没有服务端，key 打进前端就会被任何访客从浏览器开发者工具中取走，访问密码挡不住这一点（密码只管进门，进门后 key 照样暴露）。

最终决定改为 BYOK：每位使用者（包括所有者本人）在页面粘贴自己的 Gemini API key，额度与流量各自承担。由此带来三个连锁简化：

1. 无需鉴权——访客烧的是自己的 key，网站本身无资产可偷。
2. 无需 Workers 代理——纯静态 Pages 托管，零服务器成本、零运维。
3. 天然隐私友好——语音与报告数据不出使用者自己的浏览器和 Google 之间的连接。

后果：使用门槛转移给了访客（需自行到 Google AI Studio 申请免费 key），README 必须提供清晰的申请指引。

被否决的替代方案：Pages + Workers WebSocket 代理（能藏 key、能做鉴权，但多一层实时音频转发的开发与调试成本，且个人自用场景下收益不成立）。
